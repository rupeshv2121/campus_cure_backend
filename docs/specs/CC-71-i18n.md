## Problem

The roadmap's target users for this are non-teaching staff: electricians, plumbers and lab
assistants who handle complaints (CC-27), many of whom read Hindi more comfortably than English.
Every screen is English-only.

## Goal

A user can switch the app to Hindi, from the sign-in page onwards, and complete the whole complaint
journey in it: sign in, raise a complaint, track it, and, as staff, work the queue and send a fix
for confirmation.

## Scope

**Translated:** the sign-in page, with all steps of CC-62/63; the sidebar, header, profile menu,
notification panel and offline banner for every role; Raise a Complaint, including validation
messages and the auto-fill notes; My Complaints, including confirm/reject and rating; the staff
Assigned Complaints queue and its resolution modal; and every complaint status, priority and
category label.

**Not yet, still in English:** the doubt community, dashboards, admin screens, profile and settings,
and the sign-in page's marketing panel. They need the same mechanical pass. The `useLabels` hook and
the `nav` dictionary already cover their shared labels.

## Non-goals

- **Server-generated text.** Notification titles, emails, push and Telegram messages, and API error
  messages are written in English by the backend at about forty call sites. Translating them means
  storing a language per user and threading it through every `createNotification`. Worth doing, but
  a separate change.
- A language per account. The choice is stored per browser (`localStorage`), deliberately: a shared
  lab computer should follow whoever set it, not flip at each sign-in.
- Translating user content. Complaints are shown as written.

## Design

`i18next` + `react-i18next`, initialised in `main.tsx` before the first render.

| File | Role |
|---|---|
| `src/i18n/en.ts` | Source strings. `nav` is keyed by the English label itself, so the sidebar config stays readable and an untranslated item still shows |
| `src/i18n/hi.ts` | Typed against `en.ts`: a missing key fails the build |
| `src/i18n/index.ts` | Init; `setLanguage` (persists, sets `<html lang>`); `useLabels()` for statuses, priorities, categories and nav, falling back to English for any value it has never seen |
| `components/app/LanguageSwitcher.tsx` | English / हिंदी, each written in its own script so someone who cannot read the current language can still find theirs. On the sign-in page and in the header |

**Language choices.** Everyday Hindi over formal vocabulary: "शिकायत", not "परिवाद". Words people
actually say stay as spoken: प्रोजेक्टर, वाई-फ़ाई, कोड, लॉग आउट.

Validation messages in Raise a Complaint are built per call (`complaintSchema(t)`), so they follow a
language switch made mid-form.

**Fixed along the way** (Raise a Complaint):

- The duplicate-check effect cleared uploaded files and remounted the uploader whenever the text was
  shorter than 10 characters. A photo attached before typing vanished on the first keystroke. Only
  the suggestions are cleared now.
- The validated form was logged to the browser console on every submit. Removed.

## Testing

`src/i18n/translations.test.ts`: every English key exists in Hindi and is non-empty; each string
keeps exactly the same `{{placeholders}}`, which the type system cannot see; strings are actually in
Devanagari; and every sidebar label has a translation.

**Still to check by hand:** read the Hindi screens with a native reader from the target group.
Wording that is correct can still be unnatural for an electrician reading it on a phone.
